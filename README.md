# SkinsRestorer for Horizon

**SkinsRestorer** lets players on a Horizon server change their skin. A stored
skin replaces the player's signed `textures` property at login, before the
server sends the profile, so the player's own client and everyone in the
player list see it.

This is a **server-side native mod** for the Horizon mod API. It is an original
implementation of the SkinsRestorer idea; the Java plugin's code is not used.

## Requirements

The mod uses the `player_login_profile` hook, which is part of the Horizon mod
API in the accompanying API change. It needs a game build with that hook and
its SDK; a build without it refuses the mod at load.

The manifest pins Horizon `baea2549…` as the base. After the API change is
merged, update `[native].horizon` to that merge commit and rebuild.

## Commands

| Command | What it does |
| --- | --- |
| `/skin` | Shows the skin stored for you. |
| `/skin set <name>` | Looks the Minecraft account `<name>` up on Mojang's public services and stores its signed skin for you. |
| `/skin clear` | Forgets your stored skin; your own skin comes back. |
| `/skin update` | Looks the stored name up again, picking up a skin the account changed. |
| `/skin set <name> <player>` | Operators only: sets another player's skin. |
| `/skin clear <player>` | Operators only: clears another player's skin. |

A skin is applied the next time the player logs in. Telling the player to
reconnect is the honest answer until the mod API has a way to refresh an
online player's profile.

The lookup runs on a worker thread; the server tick never waits for Mojang.
The answer is kept in `config/skinsrestorer/skins.json` on the server, or the
world's `serverconfig/skinsrestorer/skins.json` when that copy exists.

## How it works

`player_login_profile` is a server hook that runs once for each accepted
login, after the name, whitelist, ban and server-full checks and before the
login success is sent. It hands the mod the UUID, the name and the profile's
properties. The mod replaces the `textures` property with the stored skin and
leaves the rest alone. The login success and the player list then carry the
changed profile.

The hook runs on the connection thread and has no `Host`, so the mod keeps its
skins in memory (loaded from its config file) and answers from them. The
profile's wire limits are 16 properties, non-empty names of 64 UTF-16 units,
values of 32767 and signatures of 1024; a stored skin that does not fit is not
sent, and the player keeps their own skin.

Skins are looked up from:

- `https://api.mojang.com/users/profiles/minecraft/<name>` for the account's
  UUID and canonical name;
- `https://sessionserver.mojang.com/session/minecraft/profile/<uuid>?unsigned=false`
  for the signed `textures` property.

The lookup runs in a worker thread and the result is applied on the next
server tick, so a slow or failing Mojang service cannot stall the server.

## Build and install

The mod source is in [`horizon-mod/`](horizon-mod/).

```sh
cd horizon-mod
horizon-launcher native-build . --instance "<instance>" --trust-native-code
```

The launcher fetches the pinned SDK into `.horizon/sdk/`, compiles the mod
against the instance's prebuilt game and makes that build the instance's game.
Native code runs with your rights, so read the source before you allow it.

`Cargo.lock` is the registry-only lock generated by
`horizon-launcher native-lock`; commit it with the mod.

## Development

The project is a flat native mod under `horizon-mod/`:

```text
horizon-mod/
  horizon-mod.toml     the mod's manifest and build pins
  Cargo.toml           depends on the SDK's horizon-mod-api, ureq, serde
  Cargo.lock           registry dependency pins
  src/lib.rs           the hooks, commands and skin lookup
```

The pure tests run with:

```sh
cargo test
```

The API change this mod needs lives in the Horizon repository:

- `crates/horizon-mod-vocab/src/hooks/player_login_profile.rs`: the hook
  declaration;
- `crates/horizon-client/src/lan/conn.rs`: the free-function target and the
  profile write-back before `LoginFinished`;
- `crates/horizon-client/src/native_client_hooks.rs` and
  `crates/horizon-client/src/entry.rs`: the connection-thread callback into
  the mod list.
